# 固定手绘的方法与技术指导

本工作流从花叔白板方法、角色路线 C 和确定性验收中整理而来；只提供当前固定画风所需的方法。来源与原哈希见 `upstream/SOURCES.json`，许可见 `THIRD_PARTY_NOTICES.md`。不需要读取或安装另一个 Skill。

## 从口播到画板

先锁定脚本与音轨，再拆意思单元，每个单元形成一块画板。人物表演先于生图：身份、年龄、眉眼嘴、肩背手脚、视线、关系和动作都对应原文，不补造情节。AI 负责人物线稿，代码负责骨架描摹、位置、大小、时机及合成；不把正式人物换成粗糙代码人形。

生图验收时逐张登记源图已经画出的物件及位置（家具、钟表、手机、文字、标志等），并在 `shots.json` 记录 `source_objects`；另列代码准备新增的对象及其原文依据 `overlay_objects`。默认一个物件只由一个图层负责；不得重复描画或遮盖源图中已有物件，除非确有口播重点且新旧图层不会重叠，审片记录须说明依据。

场景用一张横向世界白板组织，画板依次横排；镜头按音轨单元平移，绘制事件按口播词出现。单块画板不得短于 2.5 秒、不得超过 8.0 秒，板内相邻有效新笔画之间不得空档超过 4 秒；超限时按语义拆画板或重排已有事件，不添加无原文依据的装饰。先把源图已有物件和位置登记为 `source_objects`，再列出代码新增物件 `overlay_objects`；同一物件默认只由一个图层表达，新增笔画不得无必要重复描画或遮挡源图物件、人物表情和动作。每个圈、叉、勾、箭头及重点标记都要在分镜/事件表写明对应的原文短语和含义；符号语义须由该短语直接支持，无语义锚点就删除，不能从“听见/看见”推导否定或取消。字幕由原稿语义断句，不能拿另一段视频的时间表套用。构图、运镜和绘制速度的固定参数只见 `STYLE_SPEC.md`（landscape 的版式差异见 `LANDSCAPE_SPEC.md`），开头只见 `OPENING_SPEC.md`。节奏手感（写字速度、开写晚于口播、手入画出画、每块停留）和易错点参考 `WHITEBOARD_GRAMMAR_Y3.md`、`CRAFT_LESSONS.md`，冲突以前两份为准。不加入其他动画语法的弹跳、拉远或风格选择流程。

## 事件表与资源契约

- `scripts/new_project.py` 复制包内精简引擎和 `hdv`，创建人物图及手形引用；仅在项目副本打既有 Windows 补丁，原文件哈希可追溯。
- `design/config.json` 绑定本片原稿、词级时间戳和音轨。`Clock` 校验时间戳与原稿；`S()/E()` 以短语取真实起止时间，重复短语用 nth/last 定位。对不上的稿件先排查，不手调时间伪装对齐。
- `design/shots.json` 绑定镜头、原文、表演及图片；`cast.json` 保持同一角色身份。`analyze_strokes.py` 只分析图片，不改原图。`make_manifest.py` 校验逐图观察、品牌与复用限制，通过后才允许正式渲染。
- `Film.panel/hero/text/line/box/arrow/cross/check/bubble/phone/ring` 生成事件；参照模板、`LAYOUT_LIBRARY.md` 和 `examples/xiaoyu/film.py`。text 的 y 是基线，圈字用 ring，不猜椭圆坐标。人物尺寸与文字都在自己画板内。
- `Film.build()` 输出 `hand_drawn_marker` spec：duration、fps、width、height；data 含 scenes/events/captions/spriteLibrary/image；cues 声明人物源图，图片路径相对 spec。运行事件表必须处理版面、开头与窗口自检中的全部问题。
- `render_film.py` 始终以 spec 渲染；--stills 用于静帧，--out 用于整片。渲染器按 round(duration×fps) 输出帧，图片只允许 spec 声明的本地资源，页面错误或加载失败必须退出。浏览器、随机种子与所有事件时间固定，同一时刻重复渲染必须像素一致。

## 实际引擎依赖

`clip.html` 仅加载 fonts、util、paint、kit、motion、diagram 与 clip.js；`hand_drawn_marker.js` 在项目中注册唯一语法。U 来自 util，U.setStage/onStage 在 motion；DG 的手绘线依赖 KIT 点列与 PAINT.noise。五个基础库保留原文件及算法，不以逐函数裁剪破坏传递依赖。

画面字体只注册霞鹜文楷 LXGWWenKai-500 和字幕家族 PuHui-Medium（文件 NotoSansSC-500），封面单独用包内完整 Noto Sans SC TTF。引擎字体为现有 GB2312 子集：如罕见姓名报告缺字，必须记录并补齐相应字体后重验，不能把系统字体回退当作跨电脑画面一致。该限制前版即存在；不新增其他艺术字体作为“备用”。

## 技术检查与人工判断

`qa_project.py` 对 spec 检查页面错误、同帧确定性、耗时、相邻帧运动/静止/跳变，以及持续出现的文字裁切/重叠/近空白线索。缺本轮报告、空段落或确定性失败都不能通过。性能和框景数字是定位线索；镜头切换、笔画中途与被物件遮挡的文字仍须看实际帧。

完整验收按 `CHECKLISTS.md`：画板完成帧、转场边缘、开头、音画与语音、混音授权、封面 0/6 帧及静音/总帧数都要检查；深色字幕带不能误套无字幕浅底门槛。未参与制作的独立 agent 获得成片与原稿逐幕审查，实际没听或没看的项目标未验证，不能用抽帧冒充完整观看。

超出这套固定手绘能力时，明确需求、当前限制、可选做法和风险，提交改编申请；用户批准前不改变画风、运动或生产流程。包内不提供其他花叔路径，也不要求用户额外安装它们来继续本工作流。

人物笔画的填色（2026-10-16 起）：`template/engine_overrides/clips/hand_drawn_marker.js` 在笔画之外还有填色层——皮肤、阴影和粗黑块（头发）在笔画 150 px 内先于全图显出，并支持 `meta.split` 左右分区各自补行，所以画人物过程中脸和身体不再出现“最后才补上”的白斑。新项目的 engine/clips 必须取自本技能模板；旧项目若出现白斑，先换成最新模板并重渲，不改图。验收见 CHECKLISTS“画人物过程抽帧”。
